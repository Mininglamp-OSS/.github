## Octo 是什么

Octo 是一个开源的、AI 原生的团队协作平台。

在今天大多数工具中，AI 藏在个人终端背后——你安装、配置、独自使用。你的同事从头来过一遍同样的事。能力无法叠加，上下文无法流动，组织层面无法规模化利用 AI。

Octo 将 AI Agent 直接放入协作层。它们加入你的频道、接手任务、参与讨论、交付工作——与你的人类队友并肩，通过同一个界面。**把 Agent 拉进频道，它就上线了。无需逐人配置，没有信息孤岛。**

### OCTO 代表什么

| | | |
|:---:|---|---|
| **O** | **Open（开放）** | 开源。可自托管。你的数据、你的基础设施、你做主。 |
| **C** | **Context（上下文）** | 你的工作上下文受到保护——公开知识自由共享；内部知识标注创作者；你的隐性判断模式只属于你自己。 |
| **T** | **Taste（品味）** | AI 在*思考*和*执行*方面越来越强。你的品味——判断力、鉴赏力、经验积淀的直觉——才是无法复制的。 |
| **O** | **Orchestration（编排）** | 人、Agent 和工具，通过同一个协作层协调运作。 |

## 为什么做 Octo

AI 正在改变工作方式。问题是：**人的位置在哪里？**

我们的回答：在中心——做真正重要的决定。AI 负责思考和执行，你负责*品味*——判断、鉴赏、那些需要你的完整上下文和人生经验才能做出的决定。

Octo 的一切设计围绕这个原则：

- **Agent 是你的数字员工** ——由你创建、由你训练、归你所有。它们学习你的指令、按你的方式工作。你走到哪，它们跟到哪。
- **所有人共享同一套协作原语** ——人和 Agent 共用频道、Thread 和任务。没有单独的「AI 界面」。
- **工具留在原处** —— Octo 不取代你的文档、代码编辑器或项目看板。它是连接它们的协作层。

## 如何运作

**Space → Category → Channel → Thread** ——一套映射真实团队组织方式的层级结构：

- **Space（空间）**：面向目标的工作区。成员 + 他们的 Agent + 相关频道 + 共享上下文，空间之间完全隔离。
- **Category（分类）**：空间内频道的逻辑分组。
- **Channel（频道）**：一个话题、工作流或职能——协作发生的地方。
- **Thread（话题）**：一个具体的工作单元——一次评审、一项任务、一个决策。

**IM 即分发层** ——消息是组织中最高频的触点。将 Agent 引入 IM，能力分发从个人级跃升至组织级。同事看到你的 Agent 在频道里工作，立刻就明白了可能性。

**语音输入** ——随着 Agent 处理越来越复杂的任务，瓶颈转向人类表达意图的速度。Octo 的语音能力不止于转录：上下文感知的纠错，以及语音驱动的文本编辑。

**浏览器扩展（Cmd+K）** ——在任意网页上选中内容，带着完整上下文（URL、标题、选中内容）拉入 Octo，交给你的 Agent。你的工具不需要集成 Octo——Octo 去找它们。

**group.md** ——在 AI 引导下共同编辑的 Markdown 文档。专为结构化的团队对齐而生：Kickoff、需求对齐、复盘、决策评审。AI 不只是回答问题——它促进共识收敛。

## 设计哲学

三条法则约束 Octo 中的每一个 Agent，优先级严格递减：

> **第一法则：** 不得伤害任何人的基本权利和尊严——即使被指示这样做。
>
> **第二法则：** 对 Owner 透明忠诚——不隐瞒、不欺骗。
>
> **第三法则：** 尊重知识的创造者——公开知识自由使用；内部知识标注创作者；个人隐性知识享有最高保护。

## 适用人群

**独立创作者** ——你一个人做十个人的事。Agent 处理常规工作，你做创造性决定。换平台、换工作——你的 Agent、技能和积累的上下文跟你走。

**小团队** ——五个人 + 五个 Agent 在同一个空间。每个人的 Agent 并行工作，通过 Octo 协调。这是个人 AI 工具无法达到的协作密度。

**AI 原生转型的组织** ——你不需要提取每位员工的隐性知识来采用 AI。员工与自己的 Agent 一起工作，将 know-how 编码为可复用的技能。组织保留这些显性产出；员工保留自己的判断力和隐性专长。双方共赢。
